# Resource qualification: evidence contract

Phase 7A.2 develops validation-only tools, not another data plane. Production
publication, authenticated mutation, discovery membership, pool/dial identity,
deadline and streaming contracts remain those of phases five and six.

The legacy phase-six process campaigns remain replayable. The stronger resource
campaign will independently identify the gateway, load, DNS, upstream and sampler
processes. A healthy lane must validate the entire response and required trailers;
intentional cancellation and Upgrade are different denominators. Fault allowances
must identify a target, finite time window, cause and recovery deadline.

Admission closes between operations only. Started connection preparation and HTTP
work must reach a terminal record. A continuously running bounded collector must
not await Admin controls. Independent OS and authenticated resource sampling must
continue across those controls, including held streams.

The monotonic event timeline separates warm-up, steady Running, healthy recovery
while Running, quiet Running, and explicit drain/post-drain. No current pool,
snapshot or normal supervisor is required to disappear merely because business
traffic stops. Retired/exiting units and ages are checked against bounds declared
before measurement; collection never performs lifecycle maintenance.

An independent Python standard-library verifier will recompute accounting,
response expectations, fault eligibility, temporal coverage and resource curves
from raw evidence. It must reject intentionally corrupted evidence and ignore a
controller's claimed pass. Missing data remains unavailable. Artifact exhaustion
stops new admission, collects started work and records failure rather than silently
truncating errors.

Implementation is in progress. Neither this contract nor passing ordinary CI
constitutes a Linux campaign, profiler result or resource qualification.
